# Development authentication

Student catalog and My Courses extend this flow; see [student-courses.md](student-courses.md)
for current course routes, contracts, changed files and verification.

The browser calls only relative `/bff/*` URLs. The Angular development proxy forwards
them to `https://localhost:7207` with TLS certificate verification enabled.
LMS.Web retains API JWTs in its protected server-side session cache and calls
`https://localhost:7196/` server-to-server. No credential or token storage is used
in Angular. The authentication cookie and antiforgery cookie remain Secure,
HttpOnly and SameSite Strict.

## HTTPS setup (run manually)

Use the existing .NET development certificate for all three localhost HTTPS hosts.
In PowerShell in the frontend directory:

```powershell
Set-Location 'C:\Users\poloj\Anil Documents\EnterpriseLMS.Angular'
New-Item -ItemType Directory -Force .certs | Out-Null
dotnet dev-certs https --trust
dotnet dev-certs https --export-path .certs/localhost.pem --format PEM --no-password
$env:NODE_EXTRA_CA_CERTS = (Resolve-Path .certs/localhost.pem).Path
npm.cmd start -- --host localhost --port 4200
```

The export creates `localhost.pem` and `localhost.key`; the latter is a plaintext
development private key. Keep this directory local and access restricted. `.certs/`
and `*.key` are ignored. No certificates or keys were generated by this batch.
`NODE_EXTRA_CA_CERTS` adds trust for the public certificate to the Node proxy; do not
set `NODE_TLS_REJECT_UNAUTHORIZED=0` or disable proxy TLS checks. Re-export after
renewing the .NET development certificate. See the official
[dotnet dev-certs documentation](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-dev-certs).

## JSON contracts

All responses are non-cacheable. Dates are UTC ISO 8601 strings; GUIDs are strings.

| Method | Path | Request | Success |
| --- | --- | --- | --- |
| GET | `/bff/antiforgery` | None, anonymous allowed | `200 {requestToken, headerName: "X-CSRF-TOKEN"}` and Web antiforgery cookie |
| POST | `/bff/login` | JSON `{email, password}`, CSRF header | `200 {userId, expiresAt, requiresOrganizationSelection: true}` and rotated session cookie |
| GET | `/bff/session` | Cookie | `200` session response below |
| GET | `/bff/organizations` | Cookie | `200 [{id, name, code}]`, active authorized organizations only |
| POST | `/bff/organization` | JSON `{organizationId}`, CSRF header | `200` refreshed session below and rotated cookie |
| POST | `/bff/logout` | JSON `{}`, CSRF header | `204`; server session removed and cookie expired, also when already anonymous |

```typescript
interface SessionResponse {
  userId: string;
  expiresAt: string;
  selectedOrganization: { id: string; name: string; code: string; role: 'Student' | 'Instructor' | 'Admin' | null } | null;
  isSuperAdmin: boolean;
  requiresOrganizationSelection: boolean;
  homePath: string | null;
  recoveryCode: 'organization_selection_cleared' | null;
}
interface BffError {
  code: string;
  message: string;
  fieldErrors: Record<string, string[]> | null;
}
```

Session reads check stored organization/platform access through the API. Revoked
selection returns **200**, `selectedOrganization: null` and
`recoveryCode: "organization_selection_cleared"`. A rotated session retains the
account ID, JWT and absolute expiry. Current role changes are also reflected and
cached selection metadata is updated. Platform authorization is read from stored
access even with no organization selected. `homePath` describes existing MVC
destinations; Angular does not automatically navigate there.

Failures use JSON: `400 validation_failed` (safe email/password field errors),
`400 csrf_validation_failed`, `401 invalid_credentials` for rejected login,
`401 session_expired` for missing/revoked sessions, `403 access_denied`,
`429 rate_limited`, `502 authentication_service_unavailable`, and
`500 unexpected_error`. Unsupported content types/methods and unknown BFF paths
also return sanitized JSON. Login permits ten attempts per minute per observed
remote IP; the existing upstream API limiter also applies. No exceptions or
attempted credential values are serialized. An infrastructure proxy must preserve
the correct client-IP policy before deployment; forwarded-header trust is not
changed here.

## Identity and failure transitions

Startup restores `/bff/session` and obtains CSRF for the resulting identity.
Login bootstraps CSRF, submits once, obtains a fresh signed-in token, then reads the
session. Logout bootstraps, submits once, clears UI state, and obtains a fresh
anonymous token. Login failure clears the password; a lost mutation response asks
the user to reload and check the session. Neither mutation is automatically retried.
The interceptor sends the in-memory CSRF token only on canonical root-relative
unsafe `/bff/*` URLs, not API/absolute URLs, unrelated paths or safe requests.
The default cookie-reading Angular XSRF mechanism is replaced by this explicit
header mechanism because the server cookie stays HttpOnly.

401 clears UI session/CSRF state; initial anonymous restoration does not initiate
competing navigations. Guards only control UI navigation. The UI also expires at
the server-provided absolute time. Cookie authentication remains authoritative.

Existing upstream-validation outage behavior is **unchanged**: cookie validation
calls `/api/account/session` on each authenticated request; any non-success,
HTTP failure or timeout removes the cached session and rejects the cookie. Thus
an API outage during validation yields sign-in-required behavior, not an offline
session. There is no sliding renewal or refresh-token flow. Server restarts/cache
eviction also require sign-in; the current cache is process-local.

MVC `/account/*`, learner/staff/admin/platform pages, hidden antiforgery fields,
cookie protections and redirects remain. Shared session issuance rotates cookies
for both interfaces. The same browser session is shared across ports on localhost.
The Web CSP and production SPA hosting are unchanged.

## Organization selection and Angular routes

Discovery calls the existing API `/api/organizations/me` with the protected server
session. It returns only active options as `{id, name, code}`; an empty list is a
successful result. Selection accepts exactly `{organizationId: "GUID"}`. Missing,
empty or malformed IDs and unknown properties (including client roles) receive
sanitized `400 validation_failed`. Inactive, inaccessible, foreign or mismatched
context IDs receive `403 access_denied`. No membership is created. A stored
SuperAdmin may select an authorized organization with a null membership role.

Selection reuses `LearnerApi.ValidateSelection` and shared `LearnerSignIn`
issuance. The old server session is removed and the Secure/HttpOnly cookie rotated,
while the account, server-only JWT and absolute expiry are preserved. The response
uses the same session contract as GET `/bff/session`, including current stored
membership role, platform access, and discovery-verified organization name/code.
Session reads now check active discovery as well as the API context. A selection
revoked during this check is cleared with the documented 200 recovery response;
the account session remains valid. If the account is still SuperAdmin, the UI uses
the platform landing; otherwise it uses the chooser. API membership/learning
policies and MVC organization selection/redirects are unchanged.

Browser-supplied `X-Organization-Id` headers are never copied to API requests.
The server derives scope only from the validated selection. The existing Web
antiforgery filter protects selection using `X-CSRF-TOKEN` and its existing cookie;
MVC hidden tokens remain supported. Cookie validation, outages, expiry, JSON
challenges/errors and login rate limiting retain their existing behavior.

| Angular route | Verified session requirement |
| --- | --- |
| `/login` | Anonymous; signed-in accounts resolve through `/session` |
| `/session` | Compatibility entry that redirects using the mapping below |
| `/organizations` | Signed-in account; lazy chooser, explicit selection only |
| `/workspace/student` | Selected Student |
| `/workspace/student/catalog` | Selected Student; published course catalog |
| `/workspace/student/my-courses` | Selected Student; own enrollments |
| `/workspace/instructor` | Selected Instructor |
| `/workspace/admin` | Selected Admin |
| `/workspace/super-admin` | SuperAdmin with selected organization, membership optional |
| `/workspace/platform` | SuperAdmin with no selected organization |

SuperAdmin takes precedence over a membership role. Other accounts without a
selection use `/organizations`; anonymous accounts use `/login`. A role-inappropriate
workspace URL redirects to the mapped Angular route. MVC `homePath` is never used
for Angular navigation. Guards are UI navigation controls only.

The responsive shell has desktop navigation, a mobile disclosure with Escape
focus return, skip-to-content, organization switch and logout. Landings explain
which module screens are unavailable, without fabricated statistics or module
links. Organization-specific content is destroyed during revalidation/mutations;
organization names and codes are rendered as text. Session refresh discards the
chooser's previous discovery results and resets shell navigation state.

Window focus and visible-document events re-read the session and bootstrap CSRF;
duplicate events are coalesced and do not race a pending selection/logout. This
updates cross-tab organization/role changes when returning to the app. Background
tabs are not continuously polled. Selection obtains CSRF before posting once,
accepts the refreshed session, obtains fresh CSRF after rotation, then navigates.
An ambiguous selection failure hides previous workspace content until a safe
session verification (or reload). Neither selection nor logout is automatically
replayed. All session/CSRF/UI state remains in memory.
