## Concrete integration fixes

1. `core/http/bff.interceptor.ts` binds 401 cleanup to the session object present when the request began. A stale old-organization/anonymous failure still errors to its caller but cannot clear a newer verified session/CSRF or navigate it to login. Genuine current-session 401 behavior remains. Two regressions added to `core/auth/auth.service.spec.ts`.
2. `features/organizations/organization-chooser.component.ts` clears discovery on logout, verification, mutation/context uncertainty and destruction; generation/session/expiry checks reject late responses even before rendering. Previously a late response after logout could repopulate organization names. Two chooser regressions added.
3. Backend `LMS.Web/Services/BffJson.cs` shared 409 copy now refers to stored state rather than enrollment-specific instructions for quiz/grading/account callers. Generic email error copy no longer incorrectly advertises the login-only 254 limit for 256-character recovery/member contracts. Statuses, validation attributes, allowlists, CSRF and business rules are unchanged. Added `BffAuthTests` conflict regression.
4. `src/app/app.routes.spec.ts` adds `/app` navigation with root-relative BFF evidence. This adds a test, not a product feature.

This report is mirrored to backend `docs/angular-coverage-audit.md`. No missing module was implemented or authorization/assertion/TLS/CSP/business policy weakened.

## Integration and security findings

**Links:** read-only inventory loaded actual lazy route definitions: **52 component patterns, 47 literal router links, zero unmatched literal links**. Existing harness tests exercise nested named parameters. New production-base test verifies `/app/workspace/...` links and `/bff/...` requests. Dynamic IDs still require fixtures/browser testing; a literal scan proves neither authorization nor record existence. Staff report review links require an authorized stored-parent/learner check. Gradebook suppresses unavailable quiz detail links; assignment history uses stored parent IDs. Clients correctly use the unusual API-root `/{lessonId}/quiz` definition route.

**Production output/fallback:** production injects `APP_BASE_HREF=/app/`, emits `/app/` asset URLs and an index without `<base>`, preserving `base-uri 'none'`. Critical inline CSS/font inlining is disabled. Four referenced index assets exist; **23 lazy chunks**, no missing relative JS chunk references, zero source maps and no inline script/style/event/base elements. This is file inspection, not browser fetching. `Angular:Enabled` serves Web `wwwroot/app` before routing plus a `/app`-only HTML fallback. Missing dotted assets return 404, not HTML. Dotless unknown `/app` URLs reach Angular's wildcard/session handling; the fallback is prefix-scoped, not a business-route allowlist. No artifacts were deployed. Root MVC/BFF/account entry are not SPA fallbacks.

**Email links:** `AccountLinks:PublicUrl` is an explicit trusted HTTPS origin root, never request Host. Missing/empty/`Mvc` destination retains MVC. Exact `Angular` generates `/account/angular/...` entry URLs; the server privately captures tokens and redirects cleanly before SPA boot, with no resources, no-store/no-referrer and restrictive CSP. Accidental token-bearing SPA account URLs are cleaned before bootstrap and rejected. Private link cookies are root-path, HttpOnly/Secure, purpose-separated, SameSite Lax, 20 minutes; raw tokens are encrypted in server memory. Final account actions remove the private session before dispatch, including when validation later fails; reopen the original email deliberately rather than replay. Reset status checks private-session presence, not Identity token validity. Existing MVC account routes remain.

**Session/CSRF:** dev proxy forwards only `/bff/**` to HTTPS Web with `secure:true`, `changeOrigin:false`. Web uses configured trusted HTTPS API origin, disables redirects/automatic cookies and retains normal certificate validation. Auth/root host antiforgery cookies and root account-link paths permit `/app` and `/bff` to share sessions. Auth/CSRF remain Secure/HttpOnly/SameSite Strict. CSRF stays in memory, refreshes across login/logout/org changes, and protects JSON/multipart mutations. Server authorization remains authoritative for every read/range. Context blocking/identity/epoch/sequence checks detach media and reject stale data. Cross-tab refresh is on focus/visible or authoritative request, not instant synchronization; anonymous tabs do not auto-discover login elsewhere. Unfocused windows can retain cached display until revalidation. Real multi-tab races remain open despite the two concrete cleanup fixes.

**Media/CSP:** `ResponseHeadersRead` and streaming copy avoid a frontend full-file/blob fetch; valid ranges/If-Range and 206/416/Content-Range/cache validators are preserved. Every range revalidates access and parents. Canonical MIME, generated disposition, private/no-store and nosniff remain. Malformed range syntax follows existing denial behavior; use a valid out-of-bounds byte range to test 416. Native errors cannot reveal HTTP status, so HEAD probes distinguish denial from format/viewer errors. PDF iframe/response are sandboxed with download fallback; real plugin behavior can still fail. Assignment PDFs are private authorized GET/HEAD downloads, not a promised range/seeking contract. Account HTML forbids frames; authorized viewer CSP permits same-origin media/frames and validated YouTube privacy host. No policy was relaxed. Playback/PDF/YouTube, seeking/codecs, captions and accessibility remain live gaps.

**Bounds/errors:** members/Instructor choices/platform orgs/reports/gradebook/audit/staff submissions use page 1..10000, size 1..50 where those contracts apply. Invitations retain distinct page 1..100000, size 1..100 bounds. Audit UTC range is <=31 days, inclusive start/exclusive end, server defaults, deterministic timestamp/ID order; UI freezes normalized range while paging. Staff submission UI uses bounded `/submissions/page`. Catalog/My Courses/hierarchy/content/staff courses/quiz history/Student assignment history still consume existing arrays; large-data performance is unverified. BFF errors are sanitized shared JSON plus known policy allowlists; not every form has full field-level mappings. Login email <=254 differs from several administration/recovery limits <=256; no bound was changed. Values survive validation where safe, passwords/files clear as required, and ambiguous mutations are not automatically replayed.

**Secrets/artifacts:** no browser local/session storage, IndexedDB or service-worker persistence of auth/display/answer/file data was found. Existing API login necessarily returns JWT to the server-side BFF client; browser BFF DTOs do not. Admin invitation responses omit tokens/links/hashes; safe projections exclude raw paths/legacy URLs; audit metadata is allowlisted. Production JS has zero JWT-shaped literals. Neither Git tracked-file list contains private-storage/certificate paths; certificate/dist/private roots are ignored. API Content/None publish exclusions cover private media/assignments/emails. `ComputeFilesToPublish` evaluation, without publishing, yielded **67 API/127 Web candidates**, zero private-storage/certificate/source-map entries. This proves current candidates, not every future deployment. The tracked API config contains a nonempty development-style signing-key literal: supply an external environment-specific `Jwt:Key` before acceptance; do not treat the literal as secret. No value is reproduced here. No embedded password was detected in the inspected default DB string. This was not an exhaustive Git-history secret scan. App diagnostics/outbound client log suppression are inspected; actual proxy/CDN/APM/email/browser-extension logging and deployed redaction are unverified. No real token/password/private file was collected or displayed.
